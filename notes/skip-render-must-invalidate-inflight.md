# 描画を省略するときも、飛行中の描画結果は捨てる

エディタの入力ごとにプレビューを非同期で描画し、「今の入力が画面に出ているものと同じなら描画しない」という省略を入れていると、Undo で古い状態に戻ったときに古い描画結果が後から画面を上書きする。

1. 入力で描画が始まる（遅延80ms のドラフト描画）。
2. その描画が終わる前に Undo で、プレビューがすでに表示している内容に戻る。
3. 「表示中と同じ」なので描画を省略する。飛行中の描画を無効にするものが何も無い。
4. 飛行中の描画が終わり、Undo 前の文字を描く。

エディタは元に戻っているのに、プレビューとサムネイルだけ新しい文字のまま。CI の e2e で確率的に落ちて見つかった（flake ではなくアプリの競合）。

## 対処: 省略の分岐でも世代番号を進める

描画結果を受け取る側は、開始時の世代番号と今の世代番号が違えば捨てる。省略するときも世代番号を進めれば、飛行中の結果は「古い世代」として捨てられる。

```ts
createEffect(() => {
  const source = editor.fullSource()
  if (source !== render.renderedSource()) void renderPreview(source)
  // 表示中と同じに戻った（入力が描かれる前の Undo）。飛行中の描画は古いので着地させない
  else previewGeneration++
})
```

世代番号の比較だけで競合を扱っているなら、「描画しない」経路にも必ず番号を進める行を置く。番号を進め忘れる経路は、描画が要らないと判断した経路に集まりやすい。

## 再現を決定的にする

描画の遅延を 400ms に固定し、入力の 150ms 後に Undo する e2e を書いた。修正前は "Slide One typed" が残って落ち、修正後に通る。
