# LRU キャッシュの追い出しが再描画と噛み合って止まらなくなる

描画のたびにキャッシュを引き、キャッシュに何か入るたびに再描画する作りで、キャッシュに上限（LRU）を付けると、
文書が参照する量が上限を超えた時点で止まらなくなる。

1. 画像 A が届いてキャッシュに入る。上限を超えたので一番古い B を追い出し、再描画を要求する。
2. 再描画が B を引く。無いので取りに行く。
3. B が届く。上限を超えたので次に古い C を追い出し、再描画を要求する。以下繰り返し。

[[e2ee-ephemeral-attachments]] のプレビューで、64 MiB の上限に対してこれが起きうると [[pullfrog]] が指摘した。
3枚の画像を小さい上限で再現すると、500ミリ秒で639回の GET になったという。10 MB の写真なら7枚ほどで届く。

## 対処: 画面に出ているものは追い出さない

上限を「画面に出ていないものから減らす」ソフトな上限にする。

- 参照（lookup）のたびに、その ID を「今回の描画で見た」集合に入れる。
- 描画が終わったら、その集合を「画面にある」集合に移す（描画側から `rendered()` を呼ぶ）。
- 追い出しでは、今回見た集合と画面にある集合のどちらかに入っているものを飛ばす。

文書が参照する合計が上限を超えても、画面にあるものは全部メモリに残り、同じ文書を描き直す限り取得は増えない。
上限を「一部を代替表示にする」ハードな上限にする選択もあるが、ここでは表示を優先した。

別の落とし穴として、取得完了から復号・キャッシュ登録までの間に「取得中」の印を外していると、その隙に描画が
走って同じものを二重に取りに行く。印はキャッシュに入れるか諦めるまで外さない。

## 理解度チェック

```quiz
描画のたびに参照し、到着のたびに再描画する LRU キャッシュが止まらなくなる条件は?
---
画面が参照する合計が上限を超えたとき。追い出したものを次の描画がまた取りに行き、それが届くと別のものを追い出す。
```
