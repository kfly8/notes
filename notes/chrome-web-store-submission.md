# Chrome ウェブストアへの提出

掲載情報の一部は**ZIP の中の manifest から来る**ので、ダッシュボードだけ整えても反映されない。ここを知らないと、書いた原稿がそのまま捨てられる。

| 項目 | どこから来るか |
| --- | --- |
| 拡張機能名（45文字） | **manifest の `name`** |
| 概要（132文字） | **manifest の `description`** |
| 128px アイコン | **manifest の `icons`** |
| 説明（16,000文字） | ダッシュボード |
| スクリーンショット・プロモーションタイル | ダッシュボード |
| カテゴリ・言語・各種 URL | ダッシュボード |

名前と概要はダッシュボードで編集できない。**この2つは `chrome://extensions` の一覧とツールバーのツールチップにも同じ文字列が出る**ので、ストア検索向けに説明的な名前にすると、拡張一覧では少し長く感じる、という緊張がある。

日本語圏のストアでは `名前 — 説明的なタグライン` の形が主流で、**区切りはハイフンではなく em ダッシュ**が多い。

## 提出の順番

ZIP を上げてから掲載情報を埋め、**そのあとで「審査に提出」を押す。** 審査は「説明どおりの機能か」も見るので、空欄のままでは提出できない。

- 公開後に説明を直すこともできるが、**その変更も審査を通る**（新規より速い）
- 審査で却下されても、**既に公開中の掲載はそのまま**残る
- 承認後 **30 日以内**に公開する必要がある

AMO とは公開のタイミングが逆で、**AMO は自動検証を通った時点で公開され、人的審査はそのあと**になる。

## 画像の規格

スクリーンショットとプロモーションタイルは「24 ビット PNG（アルファなし）」。**アルファチャンネルが残っていると弾かれうる。**

```console
$ magick identify -format "%wx%h %[channels]\n" shot.png
1280x800 srgba 4.0     # ← アルファあり
```

中身が完全に不透明でも、チャンネルとしては残る。外すには次のようにする。見た目は変わらない。

```sh
magick in.png -background white -alpha remove -alpha off -depth 8 -strip out.png
```

ショップアイコンにはこの制限がなく、透過を残してよい。制限がかかるのはスクリーンショットとタイルだけ。

## 「何もしない拡張」はテスト手順を書かないと落ちる

[[optional-host-permissions]] の設計だと、インストール直後は**どのサイトを開いても画面が一切変わらない**。審査担当者が触っても何も起きないので、「動作を確認できなかった」で差し戻される。

テスト手順の欄（500文字）に、**画面に実際に出るラベルをそのまま引いて**手順を書く。担当者が探し回らずに済む。

## 権限の理由は疑問と同じ欄に書く

`optional_host_permissions: ["<all_urls>"]` は、専用の記入欄が無い。だが「`<all_urls>` と書いてあるのに、なぜ全サイトで動かないのか」は担当者が引っかかる点なので、**`scripting` の理由の欄**に一緒に書くと疑問と答えが同じ場所で閉じる。単一用途の欄は「何のための拡張か」を答える場所なので、権限の話を混ぜると論点がぼやける。

## EEA の取引業者申告

DSA 対応で、**取引業者（trader）か非取引業者かの申告**が必須になっている。

- **取引業者** — 自身の取引・事業・技能・職業に関わる目的で活動している者。**法的な氏名・住所・SMS の受け取れる電話番号が掲載ページに公開される**
- **非取引業者** — その外側の目的。EU の利用者には「消費者保護法上の権利が適用されない」と表示される

無料・広告なし・個人の趣味なら後者。判断基準は「職業としてエンジニアかどうか」ではなく、**その公開が商売に関わる目的で行われているか**。有料機能や広告を入れた時点で切り替えが要る。

なお**トレーダーとして登録した後に住所や氏名を直すには、いったん非取引業者に戻して認証をやり直す**必要があり、面倒。
