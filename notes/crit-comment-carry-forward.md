# crit はラウンドの途中の編集でコメントの行を取り違える

[[crit]] は、ラウンドをまたぐときにコメントの行番号を新しい内容に付け替える。基準にするのは「ラウンドで最初にファイルが変わったときの内容」なので、ファイルを編集してからコメントを足すと、そのコメントは編集前の内容に対する行として付け替えられ、別の箇所へ動く。crit v0.21.0 のソースで確認した。

## 付け替えの仕組み

1. ラウンド中にファイルの変化を検知すると、**そのラウンドで最初の変化のときだけ**、変化前の内容を `PreviousContent` に、その時点のコメントを `PreviousComments` に取っておく(`internal/session/watch.go`。`pendingEdits == 0` のときだけ取る)。
2. 次のラウンドに進むとき、`PreviousContent` から今の内容への行の差分(LCS)を取り、各コメントの行を移す(`carryForwardFileComments`)。
3. 移した先の行が、コメントを付けたときの行の文字列(`anchor`)と一致するか確かめる。一致しなければファイル全体から探し直し、見つからなければ `drifted` にする(`verifyAndCorrectPosition`)。

crit の UI だけで使う限り、ラウンドの途中の編集はすべてエージェントのもので、人間のコメントは編集が始まる前に付いている。この前提なら基準の取り方は正しい。

## 外からの編集で崩れる

ファイルを編集できるエディタから crit にコメントを送ると、前提が崩れる。

- ユーザーがファイルを編集する → ここで `PreviousContent` が編集前の内容に固定される
- そのあとでコメントを足す → 行番号は**編集後**の内容に対するもの
- 次のラウンドで、その行番号が**編集前**の内容に対するものとして付け替えられる

[[peitho]] のデッキで起きた例: スライドを1枚足してから、そのスライドの見出しにコメントした。付け替えのあと、コメントの行は次のスライドの見出しに移っていた。編集前の内容では、その行番号が次のスライドの位置だったため。

## 似た行が並ぶと、ずれたまま通る

3 の確かめは、完全一致でなくても「ほぼ一致」なら通す(`anchorSimilar`。文字列の付け足しや軽い書き換えを許すため)。スライドごとのメタデータ行のように、ほとんど同じ行が並ぶファイルでは、別の行でも「ほぼ一致」になる。

```markdown
<!-- {"key":"new-slide-4"} -->
# New Slide
...
<!-- {"key":"new-slide-2"} -->
# New Slide
```

`new-slide-4` の行に付けたコメントが `new-slide-2` の行に移っても、`drifted` にならなかった。

## 回避

行番号に頼らず、コメントの本文に対象を特定できる情報を入れておく。peitho-studio では、コメントの先頭のラベルにスライドの key を入れ(`[Slide 4 (key: new-slide-4) › heading "…"]`)、コメントがどのスライドのものかは key で決め、key がないときだけ行番号を使う。ただし、エージェントが受け取る行番号はずれたままになる。crit 側で直すなら、コメントを足した時点の内容を基準として一緒に持つ形になりそう。
