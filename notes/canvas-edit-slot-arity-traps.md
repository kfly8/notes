# canvas の編集を Markdown に戻すと、見えない形でスロットの上限を超える

[[peitho]] のスライドを、描画した canvas 上で直接編集して Markdown に書き戻す機能で、見た目には問題の無い編集が次のエラーで描画を止めることが続いた。

```
slide 1 ('cover'), line 6: slot 'body' got 2 item(s), but layout 'title-slide' allows 0..1
```

レイアウトのスロットには arity（受け入れる要素数）があり、`title-slide` の `body` は 0〜1。canvas 側の編集が Markdown のブロックを1つ増やすと超える。どれも `peitho build` を書き戻した Markdown に通すと同じエラーが再現した。

## 見出しに入った改行が、残りを別のブロックにする

見出しの canvas テキストに改行（末尾の `<br>`、ハード改行、NBSP だけの行）が入ると、`#` 見出しは最初の改行で終わるので、残りが次のブロック、つまり body の2つ目になる。

対処: 見出しの値はあらゆる改行を1つの空白に潰してから書き戻す（`slideHeadingText`）。見出しに改行を保つ手段は Markdown 側に無い。どの操作で `<br>` が入ったかは実機で未特定。

## 空にした段落が NBSP の段落として残り、要素数に数えられる

canvas の段落を空にすると、編集可能な場所を残すために NBSP 1文字の段落として書き戻していた。見た目は空で、空スロットの判定（`textContent.trim()`）も空とみなすのでスロットに書き込みを促すが、Markdown 上は段落が1つある。そこへ打ち込むと `::: {slot=body}` のブロックが追加され、2つ目になる。

対処: 空にした段落は消す（自由配置のテキストボックスがすでにそうしていた）。見出しは編集用の NBSP を残し、リストは項目ごとに消す。`body` スロットへの書き込みはフェンス無しで置く（見出しの後の素のブロックはもともと `body` に流れる）。他のスロット（subtitle、left/right）はフェンスが要る。

## 空行の連なりで、描画した本文と下書きが一致せず編集が止まる

canvas 編集の開始時に「描画済みの本文」と「下書き」を比べ、違えば古い位置情報で編集しないよう止めている。描画側は空行の連なりを1つに潰すが、下書きは打ったまま持つので、Markdown エディタで空行を3つ打つだけで canvas の全クリックが無視された。要素を消したときに前後の空行が足し合わさっても同じ。

対処: 比較は両方の空行の連なりを潰してから行い、消した要素の前後は空行を最大1つで繋ぐ（`joinBlocks`）。

## 共通して

エラーは描画のときに出るので、原因の編集から離れた場所で見つかる。切り分けは、書き戻した Markdown そのものを `peitho build` に通すのが速い。この3件はモックの描画では起きず、実エンジンで e2e を回して見つかった（[[tauri-invoke-mock-testing]]）。1件直すたびに隣の変種で再発したので、同じ操作を全レイアウトで掃く手順にした（[[bug-sweep-workflow]]）。
