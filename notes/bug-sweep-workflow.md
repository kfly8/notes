# 報告された1件のバグは、同じ操作の全変種を掃いてから直す

GUI のバグ報告は「この操作でエラーが出た」の形で来る。報告された1件だけを直すと、同じ種類の操作の隣の変種（別のレイアウト、別の要素、別の入力の仕方）で同じ原因が再発する。[[peitho]] のエディタでは、3回続けてそうなった（[[canvas-edit-slot-arity-traps]]）。最後の1回で「消してから書き直す」操作を全レイアウトで試したら、その場で2件見つかった。

この掃き方を Claude Code の Workflow（`.claude/workflows/bug-sweep.js`、引数 `{ report, deck?, pr? }`）にして、報告を受けたら必ず通す。

## 段階

1. **再現**。`origin/main` から新しい worktree を作り、実エンジン（[[tauri-invoke-mock-testing]] の実エンジン接続）をビルドし、報告のエラーを再現する。原因を `file:line` で名指しし、掃くべき軸（レイアウト × 要素 × 入力の変種）を決める。
2. **掃く**。軸の直積をデータ駆動の e2e にして実エンジンで回す。この段階では何も直さない。
3. **選別**。失敗を原因ごとに束ね、束ごとに「本当にアプリのバグか」を反証する。テストの作り物、設計上の判断が要るもの、`origin/main` でも負荷をかけると落ちる既存の flake、のどれかなら外す。反証は1束ずつ順に走らせる。worktree のビルドとサーバーを共有しているので、同時に走らせると互いの e2e を壊す。
4. **直す**。原因ごとに1コミット。それぞれに仕様テストと境界テスト、修正が無いと落ちる e2e を付ける。
5. **検証**。全部回し、別のエージェントが「掃き残した変種」を名指しする。あれば1回だけ掃き直す（最大2周）。
6. **PR**。`pr: true` で、全部通り、掃き残しが無いときだけ開く。開いたら Pullfrog と CI がきれいになるまで回す。

設計上の判断が要るものはコードで決めず、ユーザーに返す。e2e のポートは他の worktree とぶつからない番号（3021）に固定する。

## 何が効いているか

- 「直す前に掃く」順序。先に直し始めると、報告された1件に最適化した修正になる。
- 失敗を束ねてから反証する。1件ずつ直すと、同じ原因の失敗を何度も別の修正で潰すことになる。
- 掃き残しを別の目で見る。掃いた本人は自分の軸の外を見ない。

書いた時点では、スクリプトの構文と、モックのエージェントで「同時に動くのは1つだけ」「掃き残しがあれば PR を開かない」ことを確かめたところまで。実エージェントでの通し実行は未確認。
