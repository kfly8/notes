# 要素に重ねるピンは、要素に結びつけて置き直し続ける

描画した内容の上にコメントのピンを重ねるとき、クリックした座標だけを覚えておくと、レイアウトが変わった瞬間にピンが要素から外れる。ピンは「どの要素の、どこか」で覚えておき、レイアウトが変わるたびに要素の今の位置から置き直す。[[peitho]] のエディタ(peitho-studio)で、スライドのプレビューにコメントのピンを立てる機能を作ったときに踏んだ。

## 座標ではなく要素で覚える

- ピンには、要素を見つけ直すための手がかり(peitho-studio では、その要素の元になった Markdown)と、要素の箱の中での位置(幅と高さに対する割合)を持たせる。
- 描くときに要素を見つけ直し、`要素の左上 + 割合 × 要素の大きさ` を、スライドの箱に対する割合に直して置く。
- 要素が見つからないとき(書き換えられて消えたなど)に備えて、スライドに対する割合も一緒に持っておき、それを使う。

こうしておくと、PC 向けの横長とスマホ向けの縦長でスライドの組み方が変わっても、ピンは同じ要素に乗る([[fixed-aspect-canvas-on-phones]])。

## 置き直すきっかけ

表示を切り替えたときやスライドを描き直したときだけ置き直すのでは足りない。スライドは表示したあとで、自分で組み直されることがある。

- Web フォントが後から読み込まれて、文章の折り返しが変わる。横幅が狭い縦長の表示ほど、ずれが大きい。
- 画像が後から読み込まれて、下の要素が押し下げられる。

そこで、置いたあとも次の変化を見張り、変化があれば次のフレームで置き直す。

- スライドの中のすべての要素の大きさ(`ResizeObserver`。`box: 'border-box'` で見る — [[resize-observer-box-option]])
- 画像などの読み込み(スライドの根元で `load` をキャプチャで受ける。`load` はバブリングしないため)
- フォントの読み込み(`document.fonts` の `loadingdone`)

見張りはスライドや描画が変わるたびに張り直し、古いものは外す。

## クリックした位置が分からないピン

クリックした位置は、コメントを書いたウィンドウのメモリにしかない。再読み込みのあとや、別の場所で書かれたコメントには、それがない。ピンを出さないのではなく、コメントに残っている手がかり(対象の Markdown)から要素を探し、その角に置く。見つからなければスライドの角に置く。クリックした位置そのものではなくなるが、どの要素へのコメントかは伝わる。

ピンをクリックした座標だけで覚えておくと、何が起きるか。

レイアウトが変わった瞬間にピンが要素から外れる。「どの要素の、箱の中のどこか」で覚えておき、変わるたびに要素の今の位置から置き直す。

```quiz
表示を切り替えたときとスライドを描き直したときに置き直すだけでは、なぜ足りないか。

```
