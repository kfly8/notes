# flex アイテムの折り返せないテキストは幅を無視してはみ出す

flex コンテナの子孫要素は既定で `min-width: auto`。これは「その要素が縮んでよい最小サイズは、コンテンツの最小サイズまで」という意味で、テキストの場合は**折り返せる最後の箇所までの最小幅**になる。1単語（ハイフンなし、スペースなし）のテキストは折り返せないので、最小幅はそのテキスト全体の描画幅そのものになる。

## 何が起きるか

コンテナの実際の幅がその最小幅より狭いとき、`overflow` が `visible`（既定値）なら、テキストは折り返されずボックスの外に描画される。`getBoundingClientRect()` でボックス自体の位置を調べても重なりは見えない——実際にオーバーフローしているのは、そのボックスの中の子要素（テキストを持つ `span` など）。

## 実例

サイトのヘッダーで、ロゴ (`display:flex` の中の `<span>kobaken.co</span>`) と、`margin-left: auto` で右詰めしたナビゲーションが並んでいた。デスクトップ幅では問題ないが、モバイル幅（390px 程度）まで狭めると、ロゴのテキストがボックス幅を超えてはみ出し、隣のナビゲーションリンクに重なって視覚的に読めなくなり、リンクとしてタップしづらくなった。

調査時、`.site-logo` 自体の `getBoundingClientRect()` はナビゲーションと重なっていなかった。実際に重なっていたのは `.site-logo` の中の `<span>` で、その `getBoundingClientRect().right` が親のボックスを超えていた。

## 対処

コンテナ自体を折り返す。狭い画面幅でだけ `flex-wrap: wrap` にすると、ロゴとナビゲーションが2行に分かれ、重なりが解消する。

```css
@media (max-width: 480px) {
  .site-header {
    flex-wrap: wrap;
    row-gap: 10px;
  }
}
```

`min-width: 0` を明示してテキスト側を縮められるようにする手もあるが、その場合はテキスト自体が省略されるかレイアウトが崩れるため、見た目を保ちたいなら折り返しの方が素直。
