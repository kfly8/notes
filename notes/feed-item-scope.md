# 本文にマッチしたとき、どこまでを1件とみなすか

タイムラインの投稿から、キーワードに当たったものを隠したい。**テキストが当たった要素だけを隠すと、写真が残る。** フィードは本文と画像を兄弟の要素に置くため。

```
<article>                      ← 1件
  <div>投稿者名</div>
  <div>本文</div>              ← ここが当たる
  <div><img></div>             ← 兄弟。本文の中には無い
</article>
```

テキストノードから最も近いブロック要素まで遡ると、本文だけを包む小さな `div` で止まる。`div` もブロック要素なので、そこから先へは行かない。

## 「1件の器」まで広げる

`article` / `[role="article"]` / `li` / `figure` あたりまで `closest()` で遡ればよい。ただし**無条件に信じてはいけない。** ブログ記事の `<article>` はページ全体を包むので、1段落が当たっただけでページ中の画像が消える。

歯止めが要る。

## 比では判定できない

最初に「器のテキスト量が本文の何倍までなら1件」という比で判定したが、**実測すると通らなかった。**

x.com の投稿ページで測った値。

```
本文（[data-testid="tweetText"]）   21 文字
article[role="article"]           172 文字
比                                 8.19
```

**周りの定型文（名前・ハンドル・日付・カウント4つ）が、本文より長い。** 投稿が短いほど比は悪化するので、比だけを見ると短い投稿ほど「記事」と判定される。閾値を 8 や 10 に上げると、今度は本物の記事が通ってしまう。

## 絶対量で見ると分かれる

**1件の器は、そもそも小さい。** そこを先に見る。

```
器が 600 文字以下   → 比を問わず1件とみなす（ツイートは 172）
600 文字超          → 比で判定（長いが中身がほぼ本文なら1件）
```

2段にするのは、長い投稿（3000 文字のブログ記事が `li` に1件入っているような場合）を拾うため。そこは比が 1 に近くなるので、比の側で通る。逆に記事ページは、量も比も大きいので両方で落ちる。

| | 器の量 | 比 | 判定 |
| --- | --- | --- | --- |
| ツイート | 172 | 8.19 | 小さいので1件 |
| 長い投稿 | 2200 | 1.1 | 比が良いので1件 |
| 記事の1段落 | 5000 | 50 | どちらも駄目 |

## 空白のテキストノードが `<body>` にぶら下がる

別の落とし穴。`TreeWalker` で `SHOW_TEXT` を歩くと、**要素と要素のあいだの改行や字下げもテキストノードとして拾える。**

これらは自前のブロック要素を持たないので、遡ると `<body>` に着く。そして `body.textContent` は**ページ全体の文字**なので、どんなキーワードでも必ず当たる。結果、ページ中の何もかもが1件とみなされる。

`<script>` の中身も同じ経路で `<body>` にぶら下がる。

グループ化する前に落とす。

```js
const speakable = nodes.filter(
  (node) => node.nodeValue?.trim() && !node.parentElement?.closest(SKIP),
);
```

置換処理の側で空白を弾いていても、**グループ化の側でも弾かないと意味がない。** 判定に使うのはグループの器のほうなので。

React 製のサイトは要素間に空白を作らないので踏みにくく、素の HTML のサイトで出る。

## 遅延読み込みされた画像

本文を隠した時点では画像がまだ無い。あとから `MutationObserver` に来るが、**その時点で本文はもう置き換わっていて、キーワードに当たらない。**

隠した器を憶えておいて、新しく来たノードがその配下かどうかで判断する。器は `WeakSet` に入れておき、祖先を辿って含まれるか見る（`closest()` はセレクタしか取れないので使えない）。
